# Require Home Assistant 2026.10

Lightweight design note (config-only change).

**What.** Raise the minimum Home Assistant version from 2026.3.0 to 2026.10.0: `hacs.json`
(`homeassistant`), `requirements.txt` (`homeassistant~=2026.10.0`, which the tests run against)
and the conventions in `CLAUDE.md`. No integration code changes.

**Why.** Requested by the maintainer; the integration is developed and tested against the current
Home Assistant release.

**Effect on users.** HACS offers the next release only to installations on 2026.10.0 or newer;
older installations keep the version they have.

**Evidence (2026-10-27).**
- PyPI: newest Home Assistant is 2026.10.4 (requires Python >= 3.14.2).
- Under Python 3.14.6 and Home Assistant 2026.10.4: the unit tests pass (87 run, 2 skipped), also
  with `-W error::DeprecationWarning`; importing every module of the integration with `-W error`
  raises no warning that originates in this integration (two warnings come from Home Assistant's
  own `HomeAssistantApplication` and from the third-party `backoff` package).
- Review of the integration's Home Assistant API use against the installed 2026.10.4 source and
  the developer blog: nothing removed, nothing that reports a deprecation in 2026.10.

**Not covered here (separate changes).** The developer blog announces `DeviceInfo` becoming a
dataclass in 2026.11; `entity.py` builds it as a dict. The calendar coordinator's first refresh
runs inside the calendar platform (`calendar.py`), where `ConfigEntryNotReady` does not retry.
